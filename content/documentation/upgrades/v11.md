This document is intended to guide you when upgrading from GenHTTP 10.x to GenHTTP 11.

### API Rework

The dominant change of GenHTTP 11 is a reworked API layer that is better suited to represent
incoming HTTP requests and requires less work by the engine to process the data, resulting
in much higher performance (see the [HTTP Arena results](https://www.http-arena.com/)). Besides the response
content object, the middleware is now allocation-free. For general information about how the new 
API works, see the [request API documentation](../../content/concepts/request-api/).

If your project relies on direct interaction with `IRequest`, `IResponseBuilder` and
`IResponseContent`, you will need to adapt it accordingly. The contracts of high-level
handlers such as webservices or static websites did not change, so they should still
compile.

### Companions and Logging

Due to the new [logging capabilities](../../server/logging/), the `IServerCompanion` mechanism has been removed.
If you want to globally react on handled requests, you can install a
[custom concern](../../content/concerns/) instead.

### Code Generation

In older versions, the webservice frameworks used reflection for request execution by default.
With GenHTTP 11, services use [code generation](../../content/concepts/code-generation/) if available
on the current platform. Code generation will run when the server starts (via `PrepareAsync()`)
and no longer on first access.

### Body Buffering

In previous versions, the framework buffered the body of an incoming HTTP request into
a memory or file stream, depending on the size advertised by the client. This allowed
users to read the request body multiple times. With version 11, the body is no longer buffered. 
If you need to re-read the body, you can emulate the previous behavior by copying the
incoming body into a memory or temporary file stream.

```csharp
var body = request.GetBody();

if (body is not null)
{
    await using var bodyStream = body.AsStream();

    using var memoryStream = new MemoryStream();

    await bodyStream.CopyToAsync(memoryStream);

    memoryStream.Seek(0, SeekOrigin.Begin);
    
    // use the stream as needed
}
```

### Body Arguments

In previous versions, the web service framework did automatically resolve form arguments
from the incoming request body and mapped them to parameters with the matching names. While
this functionality is convenient, it added a performance penalty, even
if no form arguments were used, so this has been extracted into extension methods. 
You can either fetch the arguments from the body or let them inject as a `BodyArguments` parameter.

```csharp
using GenHTTP.Modules.IO;

var args = await body.AsBodyArgumentsAsync();
```

### Caching

The caching abstraction via `ICache` and all dependent modules have been removed, as 
the implementations turned out to be inefficient and slow. If you are using caches in your
application, consider using alternatives such as the abstraction layer provided by Microsoft instead.

### Websockets

After being declared deprecated in 10.x, the web socket handler based on [Fleck](https://github.com/statianzo/Fleck) 
has been removed in version 11. The closest replacement is the 
[functional flavor](../../content/frameworks/websockets/#functional) of the new websocket module.
